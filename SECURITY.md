# Security policy

## Supported versions

Security fixes are maintained on the default branch. Tagged releases are
supported only when the corresponding release notes say so. Repository
automation is not proof that a signed release exists.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature for this repository. Do
not open a public issue for a suspected vulnerability and do not include access
tokens, credentials, private keys, production addresses, logs, or user data in
any report.

Include the affected commit or tag, a minimal reproduction, expected and
observed behavior, and the security impact. Maintainers will acknowledge a
complete report through the private GitHub thread and coordinate disclosure
there.

## Deployment responsibility

This project is source code for self-hosting. Operators are responsible for
TLS, firewall policy, secret storage, dependency updates, backups, access
control, release verification, monitoring, and incident response in their own
environment.
